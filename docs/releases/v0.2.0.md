whoami v0.2.0 adds caller-driven agent activity to the existing deterministic SVG identity toolkit. A stable agent ID keeps its familiar face while structured events change its activity and expression. `whoami` remains a provisional product name; the package remains `@talarurus/whoami`.

## New in whoami

- **Typed activity engine:** framework-neutral TypeScript, version 1 task events, explicit idle/waiting/thinking/working/needs-input/completed/error states, independent agents, immutable snapshots, bounded accepted-event history, per-agent sequence/timestamp and task validation, and deterministic replay.
- **React activity integration:** `AgentAvatar` and `useAgentActivity` subscribe to the engine. Optional `AgentScene` is isolated in its own entry so ordinary SVG/avatar consumers do not load scene code. Existing `Face` usage remains compatible; new declarations are generated from checked source.
- **Agent Identity Studio:** `/studio` uses the public API for task/input/error/reset controls, compact mobile agent selection, an event timeline with keyboard navigation and details, explicit live/replay modes, pause/step/seek, and copyable integration code. Built-in controls simulate events; imported recordings are clearly identified as caller-supplied. No coding-agent connection is implied.
- **Local JSON recordings:** version 1 files preserve exact agent IDs/names, accepted events, the event version and pinned identity metadata. `serializeRecording` and `parseRecording` validate the complete sequence through the existing engine. Imports are bounded and atomic; malformed, unsupported and inconsistent recordings preserve the current session. Studio supports local export/import with strict UTF-8 decoding and caller-information warnings.

## Run and integrate

The repository is public. Use Node 24.21.0 or later within Node 24 and npm 11.

```sh
git clone https://github.com/talarurus/whoami.git
cd whoami
git checkout v0.2.0
npm ci
npm start
# http://localhost:4318/studio
```

`npm run build` produces the ESM package and declarations. `npm pack` creates `talarurus-whoami-0.2.0.tgz` for local installation in another application. This is **not** an npm registry installation instruction; package.json keeps `private: true` to prevent npm publication.

Public entries: `@talarurus/whoami`, `/react`, `/activity`, `/activity/react`, `/recording` and optional `/scenes`, with CSS entries documented in `docs/api.md`. React 19.2 is optional for static SVG/engine/recording users and a peer for React integration.

## Experimental surfaces and limits

- Optional laptop scenes and the manual scene playground remain experimental presentation surfaces. Existing password/chat/wall compositions are demonstrations, not authentication, messaging or monitoring services.
- The caller supplies events, increasing per-agent sequences, nondecreasing timestamps and unique task IDs across resets. One current task per agent and a fixed roster per engine are supported. Stale/out-of-order events are rejected, not buffered.
- Retain a complete accepted recording; bounded history can omit the beginning. Recording validation enforces per-agent task-ID uniqueness. Safe-integer sequence exhaustion requires a new session.
- SDK recordings are bounded to 1 MiB, 1,000 events and 32 agents. Studio uses 256 KiB, 120 events and 8 agents. IDs/names/task IDs allow 128 UTF-16 units and messages 512. Recordings may contain caller-supplied task information; review before sharing.
- Sessions stay in memory unless explicitly exported. No backend, cloud storage, accounts, telemetry, automatic persistence, automatic Codex/Claude monitoring or external approval execution is included.
- PNG export is static and browser-only; live gaze/animation and scenes are not exported. The preview server binds to loopback and has no hot reload. No production website is deployed and nothing is published to npm.
