whoami v0.3.0 adds recorded motion and local browser MP4 export to the existing agent identity toolkit. Stable IDs keep their original Blobatar faces while caller-provided lifecycle recordings drive expressions. The owner approved desktop Studio, mobile Studio and an actual 512×512 exported MP4. `whoami` and `@talarurus/whoami` retain their names.

## Added by whoami

- **Recorded-motion API:** optional framework-neutral `@talarurus/whoami/motion` compiles complete version 1 JSON recordings with an explicit millisecond origin and resolved visual policy into immutable per-agent tracks. Arbitrary timestamp sampling supports seeking, replay and independent simultaneous agents. Original event order remains authoritative, including timestamp ties; interrupted transitions preserve position, not velocity. The existing activity engine and recording system are reused.
- **Optional React rendering:** `/motion/react` exports `RecordedAgentAvatar` and `useMotionReducedPreference`. Callers own playback time. Existing `Face`, `AgentAvatar`, `AgentScene` and activity/recording APIs remain compatible.
- **Motion Studio:** the existing dark `/studio` adds shared multi-agent playback, play/pause/restart, speed, millisecond/event seeking, keyboard/touch controls and readable state/event details. Thinking and working have distinct text cues. Replay does not mutate a live session. Reduced motion uses settled poses and manual seeking.
- **Real MP4 export:** optional `/export/mp4` uses fixed sampler timestamps, WebCodecs H.264 and a lazy MP4 muxer. Studio provides square 512/1024 presets, progress, cancel, download, runtime support checks and useful errors. Multiple agents share a fixed opaque grid; export timing is independent of preview speed, rAF and refresh rate. This is offline frame encoding, not screen recording.

## Determinism and boundaries

Reproducing a frame requires the complete validated recording, pinned identity and motion revisions, explicit playback origin, resolved motion policy, timestamp and reduced-motion setting. MP4 composition also fixes roster/order, dimensions, matte and composition revision/frame index. Equivalent inputs yield equivalent SVG strings and sampling timestamps.

Browser fonts/rasterization, compressed video bytes and hardware encoder behavior are not deterministic across platforms. Historical CSS idle animation, pointer gaze and companion-scene animation are outside the sampler. Palette values can quantize; interruption continuity does not promise velocity continuity. Reduced motion is captured explicitly at export start.

## MP4 limits and verified support

- 30 fps, one-second final hold, 1..8 registered agents, even dimensions 64..2048 per axis, at most 30 seconds including the hold and 64 MiB output. Empty event recordings produce one second of idle frames. Longer recordings are rejected rather than silently trimmed.
- Opaque background; names and readable status labels; no audio, captions, alt-text metadata, live gaze or animated companion scenes. Caller-supplied labels can appear in media; review before sharing. Hosts own video controls, URL cleanup and accessible static/transcript alternatives.
- Chrome **155.0.8059.79** and Playwright WebKit **26.5** genuinely encoded and played H.264 MP4. The tested 512/1024 configurations used AVC baseline level 4.0 (`avc1.420028`); 2048 exports also succeeded at the larger configured level. Actual `isConfigSupported` checks govern availability, with graceful unsupported behavior. Secure context/device codecs/resource pressure can affect support; a successful probe is not a guarantee every export finishes.
- WebKit's observed ±1 µs encoder timestamp conversion is bounded and normalized to the original frame contract; larger changes, missing or reordered frames fail. VideoFrames/encoders/images/canvas/buffers are cleaned on success, cancellation and failure. Concurrent exports are rejected per module instance.
- Playwright WebKit and emulated mobile checks do not certify every Safari/iOS device. No physical mobile, Firefox, screen-reader or hardware-matrix certification is claimed.

## Pinned deprecated dependency — maintenance risk

**Optional video export bundles MIT `mp4-muxer@5.2.2`, which is deprecated upstream in favor of Mediabunny.** It is deliberately retained unchanged for this release as a narrowly scoped muxer for the validated H.264 path. Its original Vanilagy copyright/MIT license is included in package/site notices. The exact package and its two type-only dependencies are locked; consumers need no separate codec/type package.

Upstream deprecation creates maintenance risk: future browser compatibility, correctness or security fixes may require a separately reviewed replacement or fork. This release does not claim ongoing upstream maintenance. No replacement is attempted during release preparation. The muxer loads lazily only for optional export; ordinary core/activity/recording/motion entries stay independent of video codecs and browser capture APIs.

## Run and integrate

GitHub source distribution; use Node 24.21.0 within Node 24 and npm 11:

```sh
git clone https://github.com/talarurus/whoami.git
cd whoami
git checkout v0.3.0
npm ci
npm start
# http://localhost:4318/studio
```

`npm run build` produces ESM/declarations. `npm pack` creates `talarurus-whoami-0.3.0.tgz` for local installation in another application. This is not an npm registry installation instruction; `private:true` prevents npm publication. React 19.2 remains optional except for React integrations. See `docs/api.md`, `docs/motion-api.md`, `docs/mp4-export.md` and the typed examples.

## Validation and approval

The unchanged implementation passed 46 unit tests, strict TypeScript/build/release checks, independent installed-tarball consumption, Chrome/WebKit playback/UI/failure/cleanup checks, and historical SVG/PNG parity. AVFoundation independently parsed and decoded **2,808 frames across twelve MP4 files**, including both 30-second/900-frame boundary clips. Beginning/middle/ending frame fidelity passed against sampler SVGs. The checked-in three-agent demonstration is **512×512, H.264/MP4, 30 fps, 114 frames, 3.8 seconds, 99,462 bytes**.

Final metadata checks and exact publication proposal are recorded in `docs/releases/preparation-v0.3.0.md`. Existing browser/media evidence is retained in `docs/mp4-verification.json`; unchanged media was hash-checked rather than repeatedly re-encoded. Technical QA was performed by the implementation agent and automated tools; owner visual/media approval is recorded separately and is not universal compatibility certification.
